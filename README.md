# BioRoute

**Which model should route requests in a healthcare agent workflow?** An agent needs a fast classifier in front of it to send each request to the right workflow (drug label, clinical trials, coverage), catch requests that must go to a human compliance reviewer, and reject off-topic ones. This benchmark compares a fine-tuned open-weight encoder, a classical baseline, a self-hosted open-weight LLM, and a hosted LLM on **accuracy, calibration, latency, cost, licensing, and data handling**.

The routes match the agent in [cmg-deep-claude-agent](https://github.com/Akhilesh-Vangala/cmg-deep-claude-agent): `drug_label`, `clinical_trials`, `coverage`, `human_review`, `out_of_scope`.

## Results (150 held-out requests, 30 per route)

| Router | Macro-F1 | Human-review recall | ECE (calibration error) | Latency p50 (1 request) | Cost / 1k requests | License | Data leaves your infra? |
|---|---|---|---|---|---|---|---|
| TF-IDF + logistic regression | 0.77 | 0.77 | 0.26 (0.15 after temperature scaling) | 0.2 ms | $0 | BSD-3 | No |
| ModernBERT-base, fine-tuned (150M) | 0.77 | 0.83 | 0.085 (0.082 after scaling) | 13 ms | $0 | Apache-2.0 | No |
| **Qwen 2.5 7B, zero-shot (Ollama)** | **0.99** | **1.00** | **0.024** | 1.9 s | **$0** | Apache-2.0 | **No** |
| Claude Haiku, zero-shot (API) | 1.00 | 1.00 | 0.058 | 1.9 s* | $0.053 | Anthropic commercial terms | Yes |

Hardware: Apple M4, 16 GB. ModernBERT fine-tuning took 178 s on the laptop GPU (MPS). LLM confidence is the model's stated confidence, used as the top-label probability. \* Claude latency is measured through headless Claude Code and includes CLI start-up, so raw API latency is lower. Claude cost is API list price from measured tokens.

Per-route recall:

| Router | drug_label | clinical_trials | coverage | human_review | out_of_scope |
|---|---|---|---|---|---|
| TF-IDF + LR | 0.77 | 0.93 | 0.73 | 0.77 | 0.67 |
| ModernBERT, fine-tuned | 0.80 | 0.83 | 0.80 | 0.83 | 0.57 |
| Qwen 2.5 7B | 0.97 | 1.00 | 0.97 | 1.00 | 1.00 |

## Findings

1. **A self-hosted 7B LLM is the best option here.** Qwen 2.5 7B nearly matches Claude Haiku (0.99 vs 1.00 macro-F1), catches every compliance-review request, is the best calibrated model tested (ECE 0.024), costs nothing per call, and keeps request text on your own hardware. Its license (Apache-2.0) allows commercial self-hosting.
2. **The fine-tuned encoder is fast but not accurate enough yet.** ModernBERT is about 150x faster than either LLM (13 ms vs 1.9 s), but it reached only 0.77 macro-F1 and missed 17% of compliance-review requests. Its weakest route is `out_of_scope` (0.57).
3. **The encoder's gap is a data problem.** It was trained on 603 synthetic requests generated by Qwen and tested on hand-written ones; it learned the generator's phrasing rather than the task. The LLMs needed no training data.
4. **Calibration matters most for the classical model.** Temperature scaling cut TF-IDF's ECE from 0.26 to 0.15. ModernBERT came out of fine-tuning already well calibrated (fitted temperature 1.02), so scaling barely changed it.
5. **Recommendation.** Route with the self-hosted 7B model now. Then use it to label real request traffic and distill those labels into the encoder, so routing can eventually run in milliseconds. Re-check `human_review` recall before switching, since a missed compliance case is the costly error.

## Data

- `data/train.jsonl`: 710 requests (138 to 144 per route) generated by Qwen 2.5 7B with varied personas and drug names (`scripts/generate_train.py`), split 603 train / 107 validation. Training data was deliberately **not** generated by Claude, so the hosted model is not tested on its own phrasing.
- `data/test.jsonl`: 150 hand-written requests, 30 per route, including hard cases (coverage questions that also ask for a superiority claim, label questions that contain patient identifiers, off-label promotion phrased as a question). The test set has not been independently reviewed and is easy for frontier models; a larger, independently labeled test set from real traffic is the main next step.

## Run it

```bash
python3.13 -m venv .venv && source .venv/bin/activate
pip install -e ".[transformers]" accelerate
ollama pull qwen2.5:7b                      # for the self-hosted LLM router
python scripts/generate_train.py 6          # optional: regenerate training data
bioroute-bench --out reports/latest.json    # trains, calibrates, evaluates all routers
```

The Claude router runs through headless Claude Code (`claude -p`) with a JSON output schema; set `CLAUDE_BIN` if `claude` is not on PATH. Its test-set predictions are cached in `results/claude_haiku_test_preds.npz`; delete the file to rerun.

## Layout

```
src/bioroute/data.py        routes, definitions, dataset loading
src/bioroute/encoders.py    fine-tuning, temperature scaling, latency
src/bioroute/llm.py         Claude (headless Claude Code) and Qwen (Ollama) zero-shot routers
src/bioroute/metrics.py     ECE, Brier
src/bioroute/benchmark.py   runs every router and writes reports/latest.json
```

## Limitations

- One seed per fine-tuned model; 150 test requests. Small differences (Qwen 0.99 vs Claude 1.00) are within noise.
- BiomedBERT is supported (`encoders=` in `benchmark.run`) but was not included in this run.
- LLM confidences are self-reported, not probabilities from logits.
